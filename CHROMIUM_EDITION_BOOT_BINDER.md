# Chromium Edition Boot Binder
Derived from: CANONICAL_ARCHITECTURE.md

## Purpose

The Chromium Edition is a distribution and execution surface for the canonical Convertible Cranium architecture. It must bind to the canonical architecture without creating a second authority system.

## Boot sequence

1. Verify release lineage.
2. Verify architecture manifest.
3. Verify executable architecture gate.
4. Verify canonical Kernel snapshot identity.
5. Verify command law and governance versions.
6. Initialize offline/read-only demonstration mode.
7. Expose the operator surface.
8. Expose architecture/evidence navigation.
9. Expose available executable demonstrations.
10. Refuse to represent unimplemented A/B substrates as operational.
11. If connected operation is enabled, require the canonical governed execution path.
12. Preserve receipts and evidence for governed actions.
13. Enter recovery/COMA behavior on applicable safety faults.

## Binder contents

- Canonical architecture.
- Executable architecture manifest.
- Verification script and evidence.
- Kernel snapshot provenance.
- Synapse contract/evidence.
- Governance contract.
- Runtime safety envelope.
- Integration test plan.
- Miracle/Metabolic dual-substrate documentation.
- Acquisition map.
- Product/source lineage.

## Hard boundary

The boot binder is not an authority issuer. The UI, launcher, demo, Chromium shell, Forge, Ultra, AI surface, and boot scripts cannot grant themselves authority.

## Release gate

A release is blocked if:
- executable architecture gate fails;
- canonical source revision is unknown;
- required lineage is missing;
- governance versions do not match;
- a documented implemented box has no executable target;
- an A/B substrate is represented as implemented without implementation evidence;
- release signing requirements fail.
