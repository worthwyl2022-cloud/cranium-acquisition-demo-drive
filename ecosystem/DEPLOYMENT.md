# Linux Appliance Deployment

## What is included now

This package contains the launcher, ecosystem map, governance documents, deployment path, health checks, and a local mirror of the GitHub product repositories. The final `.iso` is generated by the build script on a Linux host with the required image-building tools installed.

## Build a bootable image

Run on Ubuntu or Debian:

```bash
sudo apt-get update
sudo apt-get install -y live-build xorriso grub-pc-bin grub-efi-amd64-bin mtools squashfs-tools debootstrap qemu-system-x86
./BUILD_ISO.sh
```

The script creates `dist/cranium-ecosystem-linux.iso`. Test it without writing to a USB:

```bash
qemu-system-x86_64 -m 4096 -enable-kvm -cdrom dist/cranium-ecosystem-linux.iso
```

To write the image to a USB, identify the correct device first with `lsblk`. Then use a dedicated imaging tool or:

```bash
sudo dd if=dist/cranium-ecosystem-linux.iso of=/dev/REPLACE_ME bs=4M status=progress conv=fsync
```

**Verify the device carefully. `dd` overwrites the selected device.**

## First boot

The image opens the Cranium AI welcome center. It starts in Explore mode with no credentials. The user can inspect the products, run health checks, and review deployment plans. Connected providers and external actions remain disabled until explicitly configured.

## Credentials

Never place GitHub tokens, API keys, private keys, or passwords in the ISO. Use an encrypted persistent partition or a secrets manager configured after first boot. Use short-lived, least-privilege credentials.

## Build boundary

A bootable image provides the operating environment and launcher. It does not make an AI model available offline by itself. Offline Cranium AI requires a locally supported model and sufficient hardware. Connected Cranium AI requires an approved provider configuration.
