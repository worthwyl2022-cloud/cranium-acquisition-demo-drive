# Convertible Cranium Commander OS

Convertible Cranium Commander OS is the migrated operational control surface for the
Convertible Cranium ecosystem.

It preserves the real lineage of the former WorthWyl Creative OS / Cranium operator
surface while moving its identity and boundary model forward.

## Role

Commander is a **supporting operational surface**.

It does not define canonical authority, canonical receipts, or canonical state.
Those responsibilities remain exclusively with `cranium-kernel`.

Commander provides the operator experience across:

- Acquisition demonstration
- Metacognitive tracking
- Creator Studio
- Resonance Lab
- Diligence Room
- Global Convertible Cranium AI interaction
- Continuity and episodic memory surfaces
- Session-level runtime protection

## Authority boundary

```
User / Voice / UI
       |
       v
Commander OS
       |
       +----> Convertible Cranium AI / orchestration
       |
       +----> Synapse evidence / assessment
       |
       +----> Miracle Memory continuity
       |
       +----> Session Circuit Breaker + rollback guard
       |
       v
cranium-kernel
       |
       +---- canonical evaluation
       +---- canonical state transition
       +---- canonical receipt / journal
```

Cognition may be generated by any permitted provider. Commander never turns a model
response, browser state, local state, or UI event into canonical authority.

## Session protection

`SessionCircuitBreaker` is intentionally non-canonical. It protects the operator
session from repeated asynchronous failures, prevents repeated execution while a
circuit is open, and invokes a rollback callback when an async action fails.

This protects the user experience and session state. It does **not** replace the
Kernel authority boundary.

## Lineage

The implementation was migrated from the archived `cranium-operator-os` repository
rather than recreated from screenshots or descriptions.

Preserved lineage includes:

- `CreatorStudioView`
- `MetacognitiveView`
- `ResonanceFieldView`
- `DiligenceDataRoom`
- `AcquisitionVideoDemo`
- `GlobalAiBar`
- continuity and episodic memory services
- acquisition-oriented documentation and evidence surfaces

Historical provenance remains documented separately. The migration does not imply
that archived code was canonical authority.

## Development

Node 24 is required.

```bash
npm ci
npm run lint
npm run build
npm run dev
```

The development server listens on port 3000.

## Evidence discipline

Commander UI state is presentation/runtime state. Any claim of authorization must be
backed by the canonical Kernel path and, where applicable, a verifiable canonical
receipt.

Do not describe Commander-local metrics, fixtures, demo data, or model output as
independent proof of Kernel behavior.
